## 1. Что это за приложение

**Сипсик Love** — мини-приложение внутри Telegram (Telegram Mini App) для пары. В центре — общий котик Сипсик:
его гладят (тапают), за тапы он получает вещи, его можно переодеть и перекрасить. Вокруг котика — инструменты для
совместной жизни: вишлист, покупки, домашние дела, календарь с планами и днями рождения, места для свиданий,
благодарности, воспоминания, записки-сюрпризы и бережные способы попросить поддержку.

Есть два режима:

- **Пара** — двое пользователей связаны приглашением, всё общее, видно действия друг друга.
- **Соло** — человек без пары: котик, списки, дневник благодарности и записки самому себе. Позже можно пригласить
  партнёра, и всё станет общим.

Приложение — это только **фронтенд** (то, что видно на экране). Данные хранятся на **сервере** (Supabase Edge
Function). Сервер, бот и база данных в этот репозиторий не входят.

## 2. Как это работает — простыми словами

Представьте приложение как ресторан:

| В ресторане        | В приложении                                    | Где лежит                       |
| ------------------ | ----------------------------------------------- | ------------------------------- |
| Зал и меню         | Экраны, кнопки, карточки                        | `src/features`, `src/shared/ui` |
| Официант           | Хранилища состояния (принимают «заказы» экрана) | `src/stores`                    |
| Телефон до кухни   | Сервисы: запросы к серверу, Telegram            | `src/services`                  |
| Кухня              | Сервер Supabase (вне репозитория)               | —                               |
| Рецептурная книга  | Правила и справочники (даты, вещи, окрасы)      | `src/domain`                    |
| Сцена с артистом   | Котик на WebGL                                  | `src/game`                      |
| Администратор зала | Каркас: навигация, шторки, синхронизация        | `src/app`                       |

Что происходит, когда вы открываете приложение:

1. Telegram открывает страницу и передаёт ей «пропуск» — подписанные данные пользователя (`initData`).
2. Приложение отправляет пропуск серверу и получает **всё состояние** пары: имена, котика, списки, планы…
3. Экраны рисуют это состояние.
4. Когда вы что-то меняете (например, добавляете покупку), экран **сразу** показывает изменение, а в фоне
   отправляет его на сервер. Сервер отвечает новым состоянием, и экран сверяется с ним.
5. Каждые 15 секунд приложение спрашивает сервер «у партнёра что-то изменилось?» и, если да, обновляется.

Котик нарисован не картинками, а **кодом через WebGL** (как в играх): он дышит, моргает, сжимается при тапе,
над ним вылетают «+1» и сердечки. Это задел, чтобы потом сделать из приложения полноценную игру со сценами.

## 3. Экраны и функции (спецификация)

### 3.1. Запуск и служебные экраны

| Ситуация              | Что видно                           | Где в коде                               |
| --------------------- | ----------------------------------- | ---------------------------------------- |
| Идёт загрузка         | Экран загрузки                      | `features/status/StatusView.vue`         |
| Открыто не в Telegram | «Открой меня в Telegram» и имя бота | там же                                   |
| Ошибка сервера        | Текст ошибки и кнопка повтора       | там же                                   |
| Нет пары и не соло    | Онбординг                           | `features/onboarding/OnboardingView.vue` |
| Пара или соло есть    | Основное приложение с 5 вкладками   | `app/App.vue` → `AppShell`               |

**Онбординг** (шаги): «Создать пару» (имя, как обращаться — он/она, дата начала отношений, имя котика),
«У меня есть приглашение» (ввод кода), «У меня нет пары, буду с Сипсиком» (соло). Если ссылка-приглашение
содержит `?join=КОД`, пара создаётся автоматически при запуске.

### 3.2. Каркас

- **Тёмная шапка (band)** с лицом котика, названием и кнопкой настроек. Нижний край — «капающая» волна.
- **Нижняя навигация** — 5 вкладок: Мы, Планы (Календарь, Места, Желания), Дом, Игры, Магазин.
- **Шторки** (выезжают снизу) — настройки, записка, быстрая покупка, SOS, дыхание, бережный разговор, покупка
  окраса. Одновременно открыта только одна.
- **Лайтбокс** — фото на весь экран.
- **Тосты** — короткие всплывающие сообщения («Добавлено», ошибки).
- **Баннеры заботы** над страницей, если партнёр попросил поддержку или написал бережное сообщение.

### 3.3. Вкладка «Мы» (`features/us`)

Шапка: живой котик (WebGL), имя и счётчик тапов, серия дней («🔥 5 дней подряд вместе»), переключатель разделов.

**Котик и тапы.** Тап по котику = +1. Тапы копятся и отправляются на сервер пачками. В день есть лимит
(`tap_cap`): после него котик «устаёт» и говорит «Я устал, подождите до завтра 😴». Если не заходить 2+ дня,
котик грустит, пока его не погладят. За накопленные тапы открываются **вещи** (24 штуки, от «Панамы abibas» за 20
тапов до «Котёнка для Сипсика» за 30 000). Вещи надеваются по слотам: голова, лапа, шея, тело, глаза, рот, сумка,
питомец, транспорт — в одном слоте одна вещь.

**Облики (окрасы).** 21 вариант: кошачьи (чёрный, рыжий, серый, трёхцветный, сиамский, смокинг, кремовый,
шоколадный, лавандовый), другие
животные (жаба, собака, лиса, панда, коровка, пингвин, бобёр, анонимус, вампир) и говорящие котики (Кот-анекдот,
Кот-поддержка, Кот-учёный). Цены и список приходят с сервера; платные покупаются за Telegram Stars. Все облики
продаются во вкладке «Магазин» (`features/coats/ShopPage.vue`).

**Говорящие котики.** У облика в `COAT_META` есть `talks` (`jokes` / `care` / `facts`). На 1-м тапе и потом на
каждом 50-м (`shouldTalk` в `domain/catPhrases.ts`) над котиком всплывает окошко с фразой (`CatPhrase.vue`,
логика — `features/us/useTalkingCat.ts`). Тапы считаются для каждого облика отдельно, на устройстве (localStorage).
Фразы — в `domain/catPhrases.ts`. Пока сервер не присылает облик в списке `coats`, в магазине он помечен «Скоро».

**Раздел «Сегодня»** (порядок карточек):

| Карточка      | Что делает                                                                  |
| ------------- | --------------------------------------------------------------------------- |
| MissedCard    | «Котик скучал» после пропуска дней                                          |
| InviteCard    | Пригласить партнёра (если его ещё нет)                                      |
| GenderCard    | Спросить, как обращаться (он/она), пока не выбрано                          |
| TipsCard      | Подсказки для новичка, скрываются навсегда после «Понятно»                  |
| UsStats       | Дней вместе, с какого дня, ближайшая годовщина (соло: котик, желания, фото) |
| QuickActions  | Быстро: желание, покупка, план на сегодня                                   |
| MoodPicker    | «Какой ты сегодня?» — своё настроение + настроение партнёра                 |
| SupportCard   | «Тяжело?» — SOS-сигнал партнёру                                             |
| TalkCard      | «Что-то задело?» — помощник бережного разговора                             |
| ThanksPrompt  | Напоминание сказать «спасибо» сегодня                                       |
| NoteCard      | Записка-сюрприз                                                             |
| DailyTasks    | Задания дня, дают котику бонусные тапы                                      |
| DailyQuestion | Вопрос дня: оба отвечают, потом видят ответы друг друга                     |
| ReceivedNotes | Три последние полученные записки                                            |
| SoonCard      | «Не забудь»: два ближайших плана и ближайший день рождения                  |
| CoatCard      | Выбор облика                                                                |
| ItemsCard     | Прогресс до следующей вещи и гардероб                                       |

**Раздел «Спасибо»** — благодарности друг другу за мелочи, лента по дням, партнёрские можно отметить сердечком.
В соло — **дневник благодарности**. **Раздел «Воспоминания»** — фото с подписью и датой; воспоминания «в этот
день в прошлые годы» поднимаются наверх.

### 3.4. Планы → «Желания» (`features/wishlist`)

Два списка: мой и партнёра (переключатель «Хочу я / Хочет …» — вверху страницы). Желание: название, цена, ссылка, заметка, фото (лимит фото — с сервера). Действия:
добавить, удалить (с подтверждением), «Сбылось», «Дарю я» (отметка видна только дарящему — сюрприз).

### 3.5. Вкладка «Дом» (`features/home`)

- **Покупки** — список с быстрыми чипами (хлеб, яйца, молоко…), отметка «куплено», «Убрать купленное». Можно открыть
  быстрой шторкой с любого экрана.
- **Обязанности** — дела с исполнителем (я/партнёр) и частотой, отметка «сделано сегодня», «поменяться», счётчик
  у каждого, «Поделить поровну».

### 3.6. Планы → «Календарь» (`features/calendar`)

Месяц с отметками (планы, дни рождения, важные даты, годовщина). Карточка выбранного дня: планы со временем,
дни рождения с возрастом, добавление плана. Отдельные карточки: **дни рождения** и **важные даты**
(разовые или ежегодные).

### 3.7. Планы → «Места» (`features/places`)

Список мест + **рулетка**: прокручивает названия с замедлением и выбирает одно. «Идём сегодня» добавляет план
«Идём: …» в календарь.

### 3.8. Шторки

| Шторка   | Назначение                                                                                    | Файл                                  |
| -------- | --------------------------------------------------------------------------------------------- | ------------------------------------- |
| settings | Имя, обращение, имя котика, дата начала, уведомления, приглашение, приватность, выход из пары | `features/settings/SettingsSheet.vue` |
| note     | Записка, которая придёт в случайный момент в течение недели                                   | `features/notes/NoteSheet.vue`        |
| shop     | Быстро добавить покупку                                                                       | `features/home/ShopSheet.vue`         |
| sos      | Выбрать, что нужно (обнять, выслушать…), и отправить сигнал партнёру                          | `features/care/SosSheet.vue`          |
| breath   | Дыхательное упражнение 4–4–6 после SOS                                                        | `features/care/BreathSheet.vue`       |
| talk     | Конструктор сообщения по ННО: факт → чувства → потребности → просьба; ИИ может смягчить текст | `features/care/TalkSheet.vue`         |
| coat     | Покупка облика за Telegram Stars                                                              | `features/coats/CoatSheet.vue`        |

### 3.9. Связь с Telegram

Вибро-отклик (haptics), цвета шапки Telegram под бренд, открытие ссылок, «Поделиться» приглашением, оплата Stars,
запрос разрешения на сообщения от бота (записки, напоминания). Всё — в `services/telegram.ts`; вне Telegram эти
вызовы безопасно ничего не делают.

### 3.10. Статические страницы (`public/`)

`privacy.html` — политика конфиденциальности. `en.html` и `privacy-en.html` — переадресация старых английских
ссылок на новое приложение.

### 3.11. Нижнее меню

Пять пунктов: **Мы · Планы · Дом · Игры · Магазин** (`app/BottomNav.vue`).

- **Планы** — родительский маршрут `/plans`. В шапке (`app/PlansBand.vue`) переключатель разделов
  **Календарь / Места / Желания**; разделы — дочерние маршруты `cal`, `go`, `wish` (адреса `#/plans/cal` и т.д.), их
  шапка и тело подставляются во вложенные `RouterView`. Последний открытый раздел запоминается
  (`stores/plans.ts`), пункт «Планы» открывает его. Старые ссылки `#/cal`, `#/go`, `#/wish` перенаправляются.
- **Игры** (`features/games`) — пока заглушка «Скоро». Новые мини-игры добавляются внутрь этой вкладки, меню не меняется.
- Какой пункт подсвечен, определяет `meta.tab` у маршрута.

## 4. Технологии и почему именно они

| Технология                  | Зачем                                                                                      |
| --------------------------- | ------------------------------------------------------------------------------------------ |
| **Vue 3 + Composition API** | Экран = компонент; логика выносится в функции `useXxx`, её легко переиспользовать и читать |
| **TypeScript (строгий)**    | Ошибки ловятся до запуска; редактор подсказывает поля данных и действия API                |
| **Pinia**                   | Общее состояние (данные пары, тапы, шторки) в одном предсказуемом месте                    |
| **vue-router (hash)**       | Вкладки = адреса `#/us`, `#/wish`…; hash работает на GitHub Pages без настройки сервера    |
| **shadcn-vue (reka-ui)**    | Готовые доступные компоненты (кнопки, шторки, переключатели), код лежит у нас и правится   |
| **Tailwind v4 + токены**    | Цвета и размеры задаются один раз, компоненты используют только смысловые имена            |
| **Pixi.js v8 (WebGL)**      | Быстрая 2D-графика как в играх: анимации, сцены, расширяемость до игры                     |
| **Vite+ (`vp`)**            | Один инструмент: дев-сервер, сборка, линтер, форматтер, тесты                              |
| **Rolldown**                | Очень быстрый сборщик (на Rust) внутри Vite+                                               |
| **Oxc (oxlint, oxfmt)**     | Очень быстрые линтер и форматтер (на Rust)                                                 |
| **@vueuse/core**            | Готовые утилиты (видимость вкладки, интервалы) вместо самописных                           |
| **vue-sonner**              | Тосты                                                                                      |
| **lucide**                  | Иконки                                                                                     |

Почему **Pixi.js**, а не three.js или голый WebGL: котик двухмерный, Pixi — лучший 2D-движок на WebGL, у него
готовые сцены, текстуры, текст и рендер в картинку. three.js нужен для 3D, голый WebGL потребовал бы писать
движок с нуля.

## 5. Структура папок и файлов

### 5.1. Корень проекта

```
.github/
  workflows/deploy.yml       ручной деплой на GitHub Pages (новая или старая версия)
  copilot-instructions.md    строгие правила для AI-ассистентов (Copilot)
CLAUDE.md                    то же для Claude (подключает файл выше)
public/                      файлы, копируемые в сборку как есть (privacy.html, переадресации)
src/                         весь код приложения
index.html                   HTML-оболочка: скрипт Telegram, шрифт, точка монтирования
vite.config.ts               настройки Vite+: сборка, алиас @, линтер, форматтер
components.json              настройки shadcn-vue (куда класть компоненты)
tsconfig*.json               настройки TypeScript
package.json, pnpm-*.yaml    зависимости и команды
README.md                    кратко: стек, команды, деплой
Description.md               этот файл
```

### 5.2. `src/` — слои

```
src/
  main.ts          точка входа: создаёт приложение, Pinia, роутер
  env.d.ts         типы переменных окружения
  assets/main.css  дизайн-токены, утилиты, базовые стили
  domain/          чистая логика и справочники
  services/        связь с внешним миром
  stores/          общее состояние
  game/            WebGL-слой (котик, сцены)
  shared/          переиспользуемое: UI-кит, общие компоненты, утилиты, конфиг
  features/        экраны и шторки, по одной папке на фичу
  app/             каркас приложения
```

**Правило зависимостей** (кто кого может импортировать):

```
app  →  features  →  shared / stores / game/vue  →  services  →  domain
```

Стрелка значит «может использовать». В обратную сторону — нельзя: `domain` не знает о Vue, сервисы не знают об
экранах, одна фича не лезет во внутренности другой. Так любую часть можно менять, не ломая остальное.

### 5.3. `domain/` — правила и справочники (без Vue, без сети)

| Файл              | Что внутри                                                                |
| ----------------- | ------------------------------------------------------------------------- |
| `types.ts`        | Формы данных с сервера: `AppState`, `Couple`, `Wish`, `Plan`, `Chore`…    |
| `dates.ts`        | Даты: сегодня, форматирование по-русски, сетка месяца, «через N дней»     |
| `moods.ts`        | Настроения котика/пользователя, обращение он/она                          |
| `items.ts`        | 24 вещи котика, пороги тапов, слоты, прогресс до следующей                |
| `coats.ts`        | 21 облик: id, название, «животное или кошка», говорящий ли котик          |
| `catalog.ts`      | Быстрые покупки, частоты дел, лимиты по умолчанию, безопасные ссылки      |
| `care.ts`         | SOS-варианты, чувства/потребности для бережного разговора, чипы «спасибо» |
| `relationship.ts` | Годовщины и важные даты                                                   |
| `ids.ts`          | Временные id для оптимистичных записей                                    |

### 5.4. `services/` — внешний мир

| Файл              | Что делает                                                                       |
| ----------------- | -------------------------------------------------------------------------------- |
| `api/contract.ts` | **Контракт API**: список всех действий сервера, их входные данные и ответ (типы) |
| `api/client.ts`   | `call(action, payload)` — POST на сервер с `initData` и сегодняшней датой        |
| `telegram.ts`     | Безопасная обёртка над Telegram SDK: haptics, ссылки, оплата, цвета              |
| `notify.ts`       | Тост + вибро; копирование в буфер                                                |
| `photo.ts`        | Чтение фото и сжатие в полноразмерное + миниатюру                                |
| `storage.ts`      | Локальное хранилище (например, «подсказки уже показаны»)                         |

### 5.5. `stores/` — общее состояние (Pinia)

| Хранилище    | Ответственность                                                                                      |
| ------------ | ---------------------------------------------------------------------------------------------------- |

## 6. Как движутся данные

### 6.1. Запуск

```
index.html → main.ts → App.vue → session.boot()
  нет initData          → status = "notg"   → «Открой в Telegram»
  call("me", {code})    → state = AppState  → status = "ready"
    нет couple          → онбординг
    есть couple         → AppShell + вкладки
```

### 6.2. Один источник правды

Сервер всегда отвечает **целым состоянием** (`AppState`). Хранилище `session` кладёт его в `state`, все экраны
читают оттуда через `computed`. Никто не хранит копии серверных данных у себя.

### 6.3. Два способа изменить данные

| Способ                                          | Когда                                                 | Что происходит                                                                                                                                        |
| ----------------------------------------------- | ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `session.mutate(action, payload, apply, okMsg)` | Мелкие частые правки: добавить покупку, отметить дело | 1) `apply` сразу правит экран; 2) запрос встаёт в очередь; 3) ответ последнего запроса заменяет состояние; при ошибке — тост и перезагрузка состояния |
| `session.act(action, payload, okMsg)`           | Важные действия: создать пару, фото, настройки, выход | Кнопки блокируются, ждём сервер, потом заменяем состояние                                                                                             |

Пока запись не подтверждена сервером, у неё временный id (начинается с `tmp`). Удалять или менять её нельзя — пользователь
увидит «Секунду, сохраняем…».

### 6.4. Тапы

Тапы считаются мгновенно, а отправляются пачкой через 0,9 с тишины (или сразу при 250 тапах; максимум 300 за
запрос). Сервер отвечает итогом и новыми вещами — появляется тост «Сипсик получил: …». При сворачивании
приложения тапы отправляются с `keepalive`, чтобы не потеряться.

### 6.5. Синхронизация с партнёром

Каждые 15 секунд (если вкладка видна) — лёгкий `ping`, сервер возвращает номер ревизии пары `rev`. Если он
изменился — загружается свежее состояние. Обновление пропускается, пока есть неотправленные изменения, чтобы
ничего не «мигало».

### 6.6. Контракт API

Все действия сервера перечислены в `services/api/contract.ts`: `wish.add`, `shop.toggle`, `plan.add` и т.д.
TypeScript не даст вызвать несуществующее действие или передать неправильные поля. Запрос всегда POST на
`config.apiUrl`, в заголовке `x-init-data` — подпись Telegram, в теле — `action`, `day` (сегодня по часам
пользователя) и данные.

## 7. Котик и WebGL (игровой слой)

### 7.1. Как нарисован котик

1. **Арт как данные.** Каждая часть котика (тело, лицо, уши, вещи) описана обычными объектами: «эллипс здесь,
   такого цвета», «путь с такими координатами» (`art/shapes.ts`). Координаты — в «дизайн-пространстве» 300×215.
2. **Сборка.** `character/compose.ts` по «образу» (`CharacterLook`: настроение, облик, надетые вещи, число тапов)
   собирает дерево фигур в правильном порядке слоёв.
3. **Отрисовка.** `art/buildArt.ts` превращает дерево в объекты Pixi (`Graphics`, `Text`, `Container`).
4. **Анимация.** `CharacterView` двигает помеченные части: дыхание, моргание, «сжатие» при тапе.

Плюс такого подхода: одни и те же данные рисуют и живого котика, и миниатюры, а любую часть позже можно заменить
на спрайт, не трогая сцены.

### 7.2. Движок

- `GameStage` — одно Pixi-приложение = один WebGL-контекст, привязанный к DOM-элементу.
- `SceneManager` — показывает одну сцену, при смене удаляет предыдущую и освобождает ресурсы.
- `Scene` — базовый класс экрана игры: `onEnter`, `onUpdate`, `onResize`, `onExit`, свои твины.
- `tweens`/`easing` — плавные анимации по ключевым кадрам.

### 7.3. Мост во Vue

- `CatStage.vue` — живая сцена. Принимает `look`, `say`, `label`; отдаёт событие `pet` и методы `boop()`,
  `shakeBubble()`. **На экране — максимум один**: браузеры ограничивают число WebGL-контекстов.
- `CharacterThumb.vue` — статичная картинка (лицо, вещь, облик целиком) в `<img>`. Рисуется одним общим
  невидимым рендерером и кэшируется, поэтому списки из десятков иконок не создают десятки контекстов.

## 9. Рецепты: что и куда добавлять

### Новая карточка на существующем экране

1. Создайте `features/<фича>/components/MyCard.vue` (`<script setup lang="ts">`).
2. Данные берите из `useSessionStore()`, действия — из `useXxx()` этой фичи или `session.mutate`.
3. Соберите из `Card`, `CardTitle`, `Button`, общих компонентов. Никаких инлайн-стилей.
4. Подключите в нужную секцию (например, `features/us/sections/TodaySection.vue`).

### Новое действие сервера

1. Сервер должен уметь это действие (вне репозитория).
2. Добавьте строку в `services/api/contract.ts`: `"thing.add": { payload: {…}; response: AppState }`.
3. Если появились новые поля в ответе — опишите их в `domain/types.ts`.
4. Вызывайте через `session.mutate(...)` (оптимистично) или `session.act(...)` (блокирующе). Если ответ — не
   состояние, используйте `call(...)` напрямую.

### Новая шторка

1. Компонент `features/<фича>/MySheet.vue` с `SheetTitle` внутри (только контент — обёртку даёт `SheetHost`).
2. Тип в `stores/sheets.ts` → `SheetProps`: `my: undefined` или `my: { id: string }`.
3. Строка в реестре `app/SheetHost.vue`: `my: defineAsyncComponent(() => import(...))`.
4. Открывать: `useSheetsStore().open("my")`.

### Новая вкладка

1. Папка `features/<фича>/` с `XxxBand.vue` (там `<h1>`) и `XxxPage.vue`.
2. id в `TABS` и маршрут в `app/router.ts` (компоненты `band` и `default`, `meta: { tab: "<id>" }`).
3. Пункт в `NAV` в `app/BottomNav.vue` (иконка из `@lucide/vue`). Сейчас сетка на 5 колонок — поправьте `grid-cols-*`.
   Не добавляйте шестой пункт: новый экран лучше сделать разделом существующей вкладки (как «Желания» в «Планах»),
   а новую мини-игру — карточкой внутри «Игр».

### Новый облик котика

1. id и название в `domain/coats.ts` (`COAT_IDS`, `COAT_META`).
2. Палитра в `game/character/palettes.ts`. Если нужен особый узор, лицо или силуэт — `PatternId` и рисование
   в `character/body.ts` / `face.ts`.
3. На сервере — цена и выдача облика.

### Новая вещь

1. Запись в `domain/items.ts` (`ITEM_IDS`, `ITEMS` — порог тапов и слот).
2. Арт в `game/character/items.ts`: `ITEM_ART` (или `CLOTHES` для одежды), `ITEM_VIEWBOX` для иконки,
   `HOLD` — если держится в лапе.
3. На сервере — тот же порог разблокировки.

### Новая игровая сцена

1. Класс `game/scenes/MyScene.ts extends Scene`: строит объекты в конструкторе/`onEnter`, анимирует в
   `onUpdate`, раскладывает в `onResize`, использует `this.tweens`.
2. Показать: `stage.scenes.show(new MyScene(...))` — предыдущая сцена удалится сама.
3. Для Vue — компонент-мост по образцу `game/vue/CatStage.vue`.

### Новый общий компонент

Если компонент нужен в 2+ фичах — `shared/components/MyThing.vue` + экспорт из `shared/components/index.ts`.
Если это новый базовый примитив (например, «Tabs») — добавьте через shadcn-vue в `shared/ui/` и сразу
переведите цвета на токены.

### Новый цвет

Сначала переменная в `:root` и `@theme inline` в `assets/main.css`, потом используйте как `bg-<имя>`.

### Новая настройка окружения

Переменная `VITE_…` в `src/env.d.ts` и значение по умолчанию в `src/shared/config.ts`. Читать только через
`config`.

### Чистая логика (расчёты, форматирование)

В `domain/`, без импорта Vue — так её легко проверить тестом и переиспользовать.

## 10. Запуск, настройки, проверка, деплой

### Команды

```sh
pnpm install      # зависимости
pnpm dev          # дев-сервер (vp dev)
pnpm typecheck    # проверка типов (vue-tsc -b)
pnpm lint         # линтер (oxlint через vp lint)
pnpm fmt          # форматирование (oxfmt через vp fmt)
pnpm build        # проверка типов + сборка в dist/
pnpm preview      # посмотреть собранную версию
```

### Настройки

`.env` не обязателен: боевой адрес API и имя бота заданы по умолчанию в `src/shared/config.ts`. Переопределить
можно в `.env.local`:

```
VITE_API_URL=https://…/functions/v1/api
VITE_BOT_USERNAME=MyTestBot
```

Секретов во фронтенде нет: сервер проверяет подпись `initData` токеном бота.

### Как проверить вне Telegram

Вне Telegram приложение показывает «Открой в Telegram». Чтобы открыть его локально как в Telegram:

1. Откройте бота в Telegram Web, запустите мини-приложение, в DevTools (контекст фрейма приложения) выполните
   `copy(Telegram.WebApp.initData)`.
2. `pnpm dev` и откройте
   `http://localhost:5173/#tgWebAppData=<encodeURIComponent(initData)>&tgWebAppVersion=8.0&tgWebAppPlatform=web`.

Скрипт Telegram сам прочитает данные из адреса. Когда они устареют — скопируйте заново. Для проверки внутри
настоящего Telegram используйте HTTPS-туннель (cloudflared/ngrok) и тестового бота.

### Деплой

GitHub Pages, workflow `.github/workflows/deploy.yml`, запуск вручную из ветки `main`:
**Actions → Deploy to GitHub Pages → Run workflow**, выбор `version`:

- `new` — собирает ветку `refactor` (`pnpm build`) и публикует `dist/`;
- `legacy` — публикует старую версию с `main` (откат).

Адрес: https://lainejakutkina.github.io/sipsik-love/. В `vite.config.ts` стоит `base: "./"`, а роутер на hash —
поэтому сайт работает по подпути. Тяжёлый Pixi вынесен в отдельный кэшируемый чанк.

## 11. Правила кода

Полный список обязательных правил — в [`.github/copilot-instructions.md`](.github/copilot-instructions.md).
Главное:

- Vue 3 только `<script setup lang="ts">`; логика — в composables, stores, domain, а не в шаблонах.
- Маленькие компоненты с одной задачей; соблюдать направление зависимостей между слоями.
- Строгий TypeScript: без `any`, без `enum` (используйте `as const`), исчерпывающие `switch`.
- Стили — только токены и варианты компонентов, без инлайн-стилей.
- Котик — только WebGL (Pixi), один `CatStage` на экран.
- Тексты интерфейса — по-русски, с правильной типографикой (« », —, …).
- Перед коммитом: `pnpm typecheck`, `pnpm lint`, `pnpm fmt`, `pnpm build` — без ошибок.
